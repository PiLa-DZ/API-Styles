# The gRPC Cheat Sheet

---

## 1. Protobuf Data Types Reference

When writing `.proto` files, map your schema fields using this layout:

| Protobuf Type         | TypeScript Type          | Notes / Best Practice                                                  |
| --------------------- | ------------------------ | ---------------------------------------------------------------------- |
| `string`              | `string`                 | UTF-8 text strings                                                     |
| `int32` / `uint32`    | `number`                 | Standard integers                                                      |
| `int64` / `double`    | `number` / `string`      | Use `longs: String` option if values exceed standard JavaScript limits |
| `bool`                | `boolean`                | True / False values                                                    |
| `repeated string`     | `string[]`               | Represents an Array collection                                         |
| `map<string, string>` | `Record<string, string>` | Key-Value lookup dictionary maps                                       |

## 2. Common Network Addresses

- `"0.0.0.0:50051"`:
  Tells the **Server** container to listen on all available network interfaces
  (local loopback, docker bridges, local network cards).

- `"127.0.0.1:50051"` or `"localhost:50051"`:
  Tells the **Client** to direct transactions strictly back to the local machine loopback adapter.

## Advanced Architecture Roadmap

Now that you have mastered Unary RPCs (simple Request-Response calls),
here is the progression path to becoming an expert backend network engineer:

### Phase 1: Streaming Capabilities

gRPC is built on top of HTTP/2,
which allows long-lived bidirectional pipelines.
You aren't limited to a single request-response layout.

- **Server Streaming:**
  The client sends one request,
  and the server keeps the connection open to stream chunks
  of data over time (e.g., streaming live data feeds or logs).

```protobuf
rpc StreamLogs(LogRequest) returns (stream LogResponse);

```

- **Client Streaming:**
  The client streams a massive payload chunk by chunk,
  and the server sends a single acknowledgment
  once it finishes processing (e.g., uploading files).

```protobuf
rpc UploadWorkoutMedia(stream Chunk) returns (UploadStatus);

```

- **Bidirectional Streaming:**
  Both client and server stream data back and forth
  concurrently over an open socket (e.g., chat applications).

### Phase 2: Production Plumbing

- **gRPC Metadata (Headers):**
  Learn how to send authorization payloads. Instead of standard REST headers,
  gRPC uses a `Metadata` class container to pass auth tokens or tracing IDs along with requests.

- **Error Handling (Status Codes):**
  gRPC doesn't use HTTP `404` or `500`.
  It relies on an explicit set of 16 status code values
  (`grpc.status.INVALID_ARGUMENT`, `grpc.status.UNAUTHENTICATED`).

- **Interceptors (Middleware):**
  Implement automated hooks that trap every incoming call to validate JWT signatures
  or track database transactions before executing service handlers.
